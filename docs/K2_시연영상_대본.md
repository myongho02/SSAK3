# K2 — 시연 영상 대본 + 녹화 가이드

> 윤명호(영상 제작 담당)가 그대로 녹화할 수 있게 한 컷씩 정리.
> 총 분량: **3분 30초** (학회 발표 영상 중 시연 파트, 전체 영상은 8~10분).
> 사전 녹화 후 발표 영상 슬라이드 5번째 자리에 삽입.

- [ ] Docker Desktop 실행, 6개 컨테이너 모두 healthy

  c.execute('DELETE FROM sessions')

- [ ] 시연용 계정 미리 생성: `demo` / `Demo1234`
- [ ] 시연용 URL 4개 미리 클립보드/메모장 준비 (아래 7번 참고)

## 3. 컷 3 — 사용자 로그인 + 단일 분석 (40초, 0:35~1:15)

### 화면
1. 브라우저로 `http://localhost:8501` 접속
2. **회원가입** 탭 선택 → `demo` / `Demo1234` 입력 → 가입
3. 자동 로그인됨 (사이드바에 `👤 demo` 표시)
4. URL 입력창에 시연용 URL #1 붙여넣기 (정상 기사 — 연합뉴스 정치)
5. **분석 요청** 클릭
6. 5초 후 결과 카드 등장

### 대본
> "사용자가 회원가입 후 본인 분석 결과를 격리된 환경에서 받습니다.
> 네이버 뉴스 URL을 입력하고 분석을 요청하면, API 서버가 RabbitMQ 큐로 작업을 발행합니다.
> Worker 중 하나가 큐에서 작업을 받아 크롤링, NLI 분석, 감성 분석, 출처 분류를 수행하고 결과를 데이터베이스에 저장합니다."

### 결과 카드 클로즈업
- 종합 점수 게이지 (예: 86점, 신뢰 가능)
- 본문 일치도 / 자극성 / 출처 막대 그래프
- 분석 근거 3섹션 (키워드 + NLI 함의/모순 + 감성)

## 4. 컷 4 — 200건 일괄 분석 + Worker 분배 시각화 (90초, 1:15~2:45) ⭐ 핵심

### 화면

**4-1. URL 200개 일괄 입력 (15초)**
대시보드의 "대량 분석" 입력창에 미리 준비한 URL 200개 (또는 50개) 붙여넣기 → **일괄 분석** 클릭.

**4-2. 진행률 바 차오르는 장면 (45초)**
사이드바 또는 메인의 "📊 분석 진행 상황" 바가 0% → 50% → 100%로 차오르는 모습.

**4-3. RabbitMQ 관리 콘솔로 큐 분배 시각화 (15초)**
다른 시크릿창에서 `http://localhost:15672` (guest/guest 로그인됨)
- Queues 탭 → news_queue 클릭
- **Consumers: 3** (Worker 3개 연결)
- Message rate 그래프가 실시간 차오름

**4-4. Worker별 처리 분포 막대 그래프 (15초)**
대시보드 메인 화면의 "Worker별 처리 현황" 막대 그래프:
- worker-1: ~67건
- worker-2: ~66건
- worker-3: ~67건
**거의 균등 분배**를 시각적으로 강조.

### 대본
> "이제 200개 URL을 일괄로 분석 요청합니다.
> RabbitMQ가 작업을 라운드로빈 방식으로 Worker 3개에 균등하게 분배합니다.
> 관리 콘솔에서 보시는 것처럼 Consumer 3개가 큐에 연결되어 동시에 메시지를 처리합니다.
>
> 처리가 진행되면서 진행률 바가 실시간으로 차오르고, 처리 완료 후 Worker별 처리 건수를 보면 67건, 66건, 67건으로 거의 균등하게 분배되었음을 확인할 수 있습니다.
>
> 이것이 메시지 큐 기반 분산 처리의 핵심 — 작업이 한 곳에 쏠리지 않고 사용 가능한 Worker에 골고루 나누어지는 부하 분산 패턴입니다."

## 5. 컷 5 — 결과 분석 + XAI 근거 (40초, 2:45~3:25)

### 화면
처리 완료 후 메인 대시보드의 통계 카드 4개:

- 평균 신뢰도: 72.3점 (예시)
- 신뢰 가능: 78건
- 의심/낮음: 24건

**등급별 분포 도넛 차트** 보여주기.

그 다음 결과 카드 1개 클릭해 상세 화면 진입 → **분석 근거 3섹션** 클로즈업:
- 📝 본문 일치도: NLI 함의 87% / 모순 5% / 키워드 매칭 6/8 (75%) / 코사인 0.42
- ⚡ 자극성: 감지 단어 0개 / 비율 0% / KR-FinBert 중립 78%
- 📌 출처: 연합뉴스 → 주요 언론사 (85점)

### 대본
> "200건 처리가 완료되었습니다. 결과는 등급별로 분포되어 시각화되며, 각 기사의 분석 결과 카드를 클릭하면 점수가 왜 그렇게 나왔는지 설명 가능한 AI(XAI) 근거가 자세히 표시됩니다.
>
> 본문 일치도는 NLI 모델의 함의/모순 확률과 함께, 코사인 유사도, 키워드 매칭 결과를 모두 보여줍니다.
> 자극성은 감지된 자극적 표현 카테고리와 KR-FinBert 감성 분석 결과를 함께 표시합니다.
> 출처는 추출된 언론사명과 해당 신뢰도 등급을 보여줍니다.
>
> 사용자는 점수 자체만이 아니라 AI가 어떤 근거로 그렇게 판단했는지 직접 검증할 수 있습니다."

## 7. 시연용 URL 준비 (4종 카테고리)

### A. 정상 기사 (높은 점수 기대) — 컷 3
```
https://n.news.naver.com/mnews/article/001/0015234567
https://n.news.naver.com/mnews/article/055/0001353790
```
주요 언론사(연합/SBS) 일반 정치/경제 보도. 평이한 톤.

### B. 200건 일괄 분석용 (컷 4)
다양한 카테고리 섞은 URL 200개 — `eval/eval_dataset.py`의 케이스 + 실제 네이버 정치/경제/사회 카테고리 URL 수집.

빠른 수집 명령:
```bash
python3 << 'EOF'
import requests, re, json
from bs4 import BeautifulSoup
urls = set()
for section in ["100", "101", "102", "103", "104", "105"]:
    r = requests.get(f"https://news.naver.com/section/{section}",
                     headers={"User-Agent":"Mozilla/5.0"}, timeout=10)
    soup = BeautifulSoup(r.text, 'html.parser')
    for a in soup.find_all('a', href=True):
        if re.match(r'https?://n\.news\.naver\.com/(mnews/)?article/\d+/\d+$', a['href']):
            urls.add(a['href'])
            if len(urls) >= 200: break
    if len(urls) >= 200: break
with open("/tmp/demo_urls_200.json", "w") as f:
    json.dump(list(urls)[:200], f)
print(f"{len(urls)}개 수집")
EOF
```

대시보드 대량분석 입력창에 다음으로 붙여넣기:
```bash
cat /tmp/demo_urls_200.json | python3 -c "import sys,json; print('\n'.join(json.load(sys.stdin)))" | pbcopy
```
