# 학교 발표 라이브 시연 대본 (3~4분)

> **현장 라이브 시연** — 팀장이 직접 화면을 조작하며 발표자(또는 본인)가 멘트 진행.
> 경기대 학과 발표용. 학회용 `시연_시나리오.md`와 별개.
> 검증일: 2026-05-15 / 시연 URL 7건 main 시스템에서 동작 확인 완료.

---

## 역할 정의

| 역할 | 담당 |
|---|---|
| **시연자** (보통 팀장) | 화면 공유 + 마우스/키보드 조작 + Streamlit 사이드바 변경 |
| **발표자** | 멘트 진행 + 청중 반응 관리 |
| **(겸직 가능)** | 시연자 = 발표자일 경우 멘트하면서 조작 — 더 천천히 |

> 본 대본은 **시연자 [액션]** + **발표자 [멘트]** 두 trace로 분리되어 있어
> 한 사람이 둘 다 맡을 때는 액션 → 멘트 순서로 흘리면 됨.

---

## 발표 전 30분 준비 (현장에서)

```bash
cd ~/SSAK3
docker compose up -d
docker compose ps                # 6개 컨테이너 모두 Up 확인
python3 demo_seed.py             # ⚡ 7건 시드 + 캐시 적중률 ↑
open http://localhost:8501       # 대시보드 미리 열어둠
```

**시연자 사전 체크리스트**:
- [ ] 6개 컨테이너 모두 `Up (healthy)` 확인
- [ ] Dashboard 좌측 사이드바에서 분야 프리셋 셀렉트박스 보이는지
- [ ] 가중치/임계치 슬라이더 expander 한 번 펼쳤다 닫기
- [ ] 분석 이력에 demo_seed가 만든 7건 모두 보이는지
- [ ] **메모장에 시연용 URL 7개 미리 복사해두기** (입력 시 시간 절약)
- [ ] 화면 공유 → 청중 시야에서 글자 잘리지 않는지 확인 (필요 시 줌인)
- [ ] 인터넷 연결 확인 (외부 URL 크롤링용)

## 라이브 시연 구성 (총 약 4분)

### 구간 1 — 시스템 가동 확인 (15초)

#### 시연자 액션
1. 화면 공유 시작 → 터미널 띄우기
2. 명령 입력:
   ```bash
   docker compose ps
   ```
3. 청중이 보기 좋게 출력 줄을 잠시 정지 (드래그 안 함, 자연스럽게)

#### 발표자 멘트 (15초)
> "RabbitMQ, Flask API, 3개 Worker 컨테이너, Streamlit 대시보드 — 6개 마이크로 서비스가 Docker Compose 한 줄로 통합 가동되고 있습니다. **healthy 표시가 시스템 안정성을 의미**합니다."

---

### 구간 2 — 분산 처리 증명 (15초)

#### 시연자 액션
1. 다음 명령 3번 연속 입력 (또는 한 줄에 `&&`로):
   ```bash
   docker exec ssak3-worker-1-1 hostname
   docker exec ssak3-worker-2-1 hostname
   docker exec ssak3-worker-3-1 hostname
   ```
2. 출력에서 **3개의 서로 다른 12자리 컨테이너 ID** 보이도록 잠깐 정지

#### 발표자 멘트 (15초)
> "각 Worker는 **독립된 컨테이너 ID를 갖는 별개 노드**로 동작합니다. 단일 머신이지만 컨테이너 격리가 보장되어, 그대로 클라우드 멀티 호스트로 확장 가능한 구조입니다."

---

### 구간 3 — 정상 기사 분석 (45초)

#### 시연자 액션
1. 터미널 → Streamlit 대시보드 창으로 전환 (`Cmd+Tab`)
2. 단일 URL 분석 입력칸에 메모장의 **URL 1번** 붙여넣기:
   ```
   https://www.yna.co.kr/view/AKR20260515145500063
   ```
3. **분석 시작** 버튼 클릭
4. 결과 카드가 나타나면 **각 지표 점수**가 보이도록 스크롤

#### 발표자 멘트 (멈춤 없이 45초)
> "주요 통신사 연합뉴스의 정상 정치 기사를 입력합니다.
> ⏱ (분석 진행) NLI 모델이 제목과 본문의 함의 관계를 분석하는 중입니다.
> ✅ (결과 나옴) **종합 86.8점, 신뢰 가능 등급**입니다.
> 본문 일치도 79.2점 — NLI 함의 막대가 녹색으로 표시되고,
> 자극성 97.5점 — 자극 단어 검출 0건,
> 출처 85.0점 — yna.co.kr이 주요 언론사로 분류됐습니다.
> **결과 카드 우측에 각 지표별 근거가 함께 표시**되어,
> AI가 왜 이 판정을 내렸는지 사용자가 직접 확인할 수 있습니다.
> 처리 시간은 약 0.76초입니다."

#### 시연자 보조 액션 (멘트 중)
- "본문 일치도 79.2" 부분에서 NLI 함의 막대를 마우스로 가리킴
- "자극 단어 검출 0건" 부분에서 자극성 섹션을 보여줌

### 구간 4 — 자극성 기사 분석 (45초)

#### 시연자 액션
1. 같은 입력칸에 **URL 2번** 붙여넣기:
   ```
   https://www.mk.co.kr/news/society/12046305
   ```
2. **분석 시작** 클릭
3. 결과 카드 — **자극 단어 하이라이트** (거짓말 / 속여 / 챙긴) 보이도록 스크롤

#### 발표자 멘트 (45초)
> "다음은 자극적 표현이 많은 사회 기사입니다. 제목 '임신했다 알고보니 거짓말, 남친 속여 1천만원 챙긴'을 분석해 봅니다.
> ✅ (결과) **종합 42.0점, 의심 기사 등급**.
> 시각적으로 보이듯 자극 단어 사전이 **거짓말·속여·챙긴을 검출**해 자극성 점수가 57.2까지 떨어졌고,
> NLI 모델이 제목-본문 함의가 낮다고 판정해 본문 일치도가 19.9점으로 급락했습니다.
> 정상 86.8점 vs 의심 42점 — **약 44점의 명확한 분리**가 시각적으로 드러납니다."

#### 시연자 보조 액션
- "거짓말·속여·챙긴 검출" 부분에서 자극 단어 하이라이트를 마우스로 가리킴

### 구간 5 — 🌟 사용자화 라이브 변경 (45초, 학교 발표 핵심)

> **이 구간이 학교 발표의 가장 큰 차별점**. 천천히, 청중이 시각적 변화를 따라올 수 있게.

#### 시연자 액션
1. 같은 자극성 기사(`12046305`) 결과 화면 유지
2. **좌측 사이드바**로 마우스 이동
3. `📐 분석 모델` 또는 `🎚️ 분석 사용자화` 섹션 찾기
4. **분야 프리셋** 셀렉트박스 클릭
5. `[일반 (기본값)]` → `[연예 — 자극성 비중↑]` 선택
6. 슬라이더가 자동 변경되는 모습이 보이도록 잠시 정지 (1~2초)
7. 결과 카드 종합 점수가 재계산되어 변화 확인

#### 발표자 멘트 (45초)
> "**여기가 PRISM의 가장 큰 차별점**입니다.
> 학계 기본 가중치 45/35/20은 모든 분야에 일률 적용되지만, 분야마다 특성이 다릅니다.
> 연예 기사는 자극적 표현이 흔하므로 임계치를 완화해야 하고,
> 정치 기사는 출처 비중을 더 높여야 합니다.
> ⏱ (시연자 사이드바 조작 중) **사이드바에서 분야 프리셋을 [연예]로 바꿔보겠습니다.**
> ✅ (변화 발생) 같은 raw 점수에 가중치와 임계치만 즉시 재계산되어 새 등급이 표시됩니다.
> 이것이 **'AI 판정을 사용자가 이해하고 통제할 수 있다'는 XAI 철학의 구현**입니다."

#### 시연자 보조 액션 (멘트 끝부분)
- 사이드바의 변경된 가중치 (35/45/20) + 임계치 (75/55/35)를 마우스로 가리킴
- 다시 [일반]으로 돌려놓기 (다음 시연에 영향 없도록)

### 구간 6 — 대량 분산 분석 (45초)

#### 시연자 액션
1. 대시보드 상단 탭/메뉴에서 **대량 분석**으로 전환

5. 처리 완료 후 등급별 분포 또는 결과 카드 일람 표시

#### 발표자 멘트 (45초)
> "마지막으로 7건 일괄 분석으로 분산 처리를 보여드립니다.
> ⏱ (전송 직후) RabbitMQ 큐가 작업을 3개 Worker에 라운드로빈 분배합니다.
> ⏱ (처리 중) **사이드바 막대그래프에서 Worker별 처리량이 거의 균등하게 증가**합니다.
> 캐시는 출처 캐시 97% 적중으로 같은 도메인 반복 처리 시 매우 빠릅니다.
> 실험 측정에서는 1,000건 처리 시 3-Worker 구성으로 **시간당 약 1만 3천 6백 건의 처리량**을 검증했습니다."

#### 시연자 보조 액션
- Worker 분배 그래프가 차오르는 동안 마우스로 가리킴
- 캐시 적중률 위젯 (사이드바 우측 또는 시스템 상태)을 가리킴

## 🆘 라이브 시연 중 막혔을 때 — 즉석 대응

> 발표자는 멘트로 자연스럽게 시간을 끌고, 시연자는 빠르게 복구.

### 케이스 1 — 분석이 5초 넘게 결과 안 나옴
- **시연자**: 새로고침 (F5) 또는 **Rerun** 버튼 클릭. 안 되면 다음 URL로 넘어감.
- **발표자 자연스러운 멘트**:
  > "분석은 비동기로 진행되어 결과가 큐 처리 순서에 따라 도착합니다. 다른 사례부터 보여드리겠습니다."

### 케이스 2 — URL이 404 또는 분석 불가 등급으로 나옴
- **시연자**: 즉시 다음 URL 시도 (memo의 7개 중 다음 것)
- **발표자**:
  > "URL이 만료되었네요. **본 시스템도 본문 추출 실패 시 '분석 불가' 등급으로 명시적으로 표시**해 잘못된 점수가 산출되지 않도록 설계했습니다. 다음 URL로 진행하겠습니다."

### 케이스 3 — Worker 컨테이너 죽음 (드물지만)
- **시연자**: 별도 터미널에서 즉시 `docker compose start worker-1 worker-2 worker-3` (3초 내)
- **발표자**:
  > "RabbitMQ 큐가 작업을 보존하므로 Worker 재시작 후에도 같은 작업이 자동으로 재처리됩니다. 이것이 메시지 큐 기반 분산 처리의 장점입니다."

### 케이스 4 — Streamlit 화면이 뻗어버림 (Rerun 안 됨)
- **시연자**: 별도 탭에서 `http://localhost:8501` 다시 열기
- **발표자**:
  > "(자연스럽게) Streamlit이 분석 결과 카드 렌더링 중인 모양입니다. 새 탭에서 다시 열어보겠습니다."

### 케이스 5 — 인터넷 끊김 (외부 크롤링 불가)
- **시연자**: **demo_seed가 미리 캐싱한 결과로 시연** — DB에 이미 7건 분석이 있으니 분석 이력 탭에서 결과 보여줌
- **발표자**:
  > "이 시스템의 LRU 캐시 덕분에 미리 분석된 결과를 즉시 표시할 수 있습니다. 처리 시간 1.5초가 0.22초로 단축되는 캐시 효과입니다."

### 케이스 6 — 시연자가 멘트 중 사이드바를 잘못 건드림
- **시연자**: 당황 말고 분야 프리셋을 다시 [일반]으로 돌려놓기
- **발표자** (자연스럽게):
  > "잠시 다른 프리셋이 잡혔네요. 이렇게 **여러 분야 모드를 즉시 전환 가능**한 것이 사용자화의 강점입니다."

## 발표 직전 5분 최종 점검

- [ ] `docker compose ps` — 6개 모두 Up + (healthy)
- [ ] `curl http://localhost:5001/` — `{"status":"running"}` 응답
- [ ] `http://localhost:8501` — 대시보드 로드 + 분석 이력 7건 표시

- [ ] 화면 공유 미리 테스트 (대시보드 + 터미널 2개 창 전환 자연스러운지)

- [ ] **부드러운 마우스 움직임 연습** — 사이드바·결과 카드 사이 전환

## 비상 fallback — 라이브가 완전히 막힐 때

라이브 시연이 **연속 2번 이상 실패**하면 발표자가 결단:

> "라이브 분석이 일시적으로 지연되고 있어, 사전에 분석된 결과 화면으로 진행하겠습니다."

→ 분석 이력 탭에서 미리 시드된 7건의 결과 카드를 차례로 보여줌.
→ 또는 **PPT 슬라이드 8(실험 결과)**에서 1,000건 측정 결과를 더 풀어 설명.
