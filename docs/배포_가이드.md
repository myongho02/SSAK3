# SSAK3 운영 배포 가이드

> 본 문서는 SSAK3 시스템을 학회 시연 / 데모 / 소규모 운영 수준으로 가동하는 절차를 다룹니다.
> 작성: 2026-05-06

---

## 1. 1줄 시작 (로컬 가동)

```bash
cd ~/SSAK3
docker compose up -d --build
docker compose ps     # 6개 컨테이너 모두 Up + healthy 확인
```

접속:
- 대시보드: http://localhost:8501 (일반 사용자)
- API: http://localhost:5001
- RabbitMQ 관리: http://localhost:15672 (운영자 전용, 외부 차단됨)

종료:
```bash
docker compose down       # 컨테이너만 종료 (DB/볼륨 보존)
docker compose down -v    # 볼륨까지 삭제 (DB 초기화)
```

## 2. 외부 접속 (ngrok 터널 — 학회 시연 / 데모)

### 2.1 ngrok Authtoken 발급 (1회만)
1. https://dashboard.ngrok.com 회원가입 (무료)
2. https://dashboard.ngrok.com/get-started/your-authtoken 에서 토큰 복사

### 2.2 환경 설정
```bash
cp .env.example .env
# .env 파일을 열어서 NGROK_AUTHTOKEN= 뒤에 토큰 붙여넣기
```

### 2.3 터널 가동
```bash
# 일반 가동 + ngrok 함께
docker compose --profile tunnel up -d

# 발급된 외부 URL 확인
open http://localhost:4040
# 또는
docker compose logs ngrok | grep "url=https"
```

발급된 URL (예: `https://abc-123-xyz.ngrok-free.app`)을 학회 심사위원/시연 대상에게 공유하면 인터넷 어디서든 접속 가능.

### 2.4 보안 주의
- 무료 plan은 매번 URL이 바뀝니다 (재기동 시)
- ngrok 무료 plan은 첫 접속 시 인터스티셜 페이지가 한 번 뜰 수 있습니다 ("Visit Site" 클릭)
- API/RabbitMQ는 ngrok 터널을 통해 노출되지 않습니다 (대시보드만 노출)

## 3. 운영 보안 체크리스트

### 3.1 자격증명 변경 (실제 운영 시)
- `.env`에서 RabbitMQ 자격증명 변경
  ```
  RABBITMQ_USER=ssak3_admin
  RABBITMQ_PASS=<강력한_랜덤_문자열>
  ```
- 회원가입 비밀번호: 영문+숫자 8자 이상 강제 (이미 적용됨)

### 3.2 기본 보안 헤더 (이미 적용됨)
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: SAMEORIGIN`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Strict-Transport-Security` (HTTPS 환경에서 효과)

### 3.3 Rate Limit (이미 적용됨)
- 회원가입: 분당 5회
- 로그인: 분당 10회
- 분석: 분당 60회 (단건) / 10회 (대량)
- 비밀번호 변경 / 회원 탈퇴: 분당 3회

### 3.4 외부 차단 (docker-compose 설정)
- RabbitMQ AMQP 포트(5672): 외부 노출 X (내부 네트워크만)
- RabbitMQ 관리 콘솔(15672): 127.0.0.1 바인딩 (호스트에서만)
- API: 5001 노출 (대시보드 직접 호출용 / ngrok 터널은 대시보드만)

## 4. 회원 관리

### 4.1 일반 사용자 흐름
1. http://localhost:8501 접속 → 회원가입 (영문+숫자 8자+)
2. 분석 요청 → 본인 결과만 노출
3. "내 통계" 페이지에서 분석 통계 + CSV 내보내기
4. "계정 설정"에서 비밀번호 변경 / 회원 탈퇴

### 4.2 비회원 모드
- 로그인 게이트에서 "👀 비회원으로 둘러보기" 선택
- 비회원끼리는 결과 공유 (user_id IS NULL 그룹)
- 회원 데이터와는 완전 격리

### 4.3 회원 탈퇴 (GDPR 수준)
- 본인 분석 결과 + jobs + 세션 + 사용자 row 모두 영구 삭제
- 비밀번호 + 아이디 재확인 후 진행
- 복구 불가능

## 5. 시스템 모니터링

### 5.1 헬스체크
```bash
docker compose ps
# 모든 서비스가 (healthy) 상태여야 정상
```

### 5.2 로그 확인
```bash
# 전체
docker compose logs -f

# 특정 서비스
docker compose logs -f api
docker compose logs -f worker-1
docker compose logs -f dashboard

# 에러만
docker compose logs api 2>&1 | grep -iE "error|exception|traceback"
```

### 5.3 RabbitMQ 큐 상태 (운영자용)
http://localhost:15672 로그인 (`.env`의 `RABBITMQ_USER`/`RABBITMQ_PASS`)
- Queues 탭 → news_queue
  - Messages: 대기 중 작업 수
  - Consumers: 현재 연결된 Worker 수 (정상이면 3)
  - Message rates: 처리 속도

## 6. 백업 / 복구

### 6.1 DB 백업
```bash
# 현재 DB를 컨테이너에서 호스트로 복사
docker compose exec api sqlite3 /app/data/results.db ".backup '/app/data/backup.db'"
docker compose cp api:/app/data/backup.db ./ssak3_backup_$(date +%Y%m%d).db
```

### 6.2 DB 복구
```bash
# 1) 컨테이너 정지
docker compose stop api worker-1 worker-2 worker-3

# 2) 백업 파일을 볼륨으로 복원
docker compose cp ./ssak3_backup_YYYYMMDD.db api:/app/data/results.db

# 3) 재기동
docker compose up -d
```

## 7. 트러블슈팅

| 증상 | 원인 / 조치 |
|---|---|
| 컨테이너가 healthy 안 됨 | `docker compose logs <서비스>` 확인. 모델 로딩 중일 수 있음 (15초 대기) |
| 분석 시 404 (네이버 뉴스) | URL이 만료되었거나 형식 오류. 다른 URL로 재시도 |
| 큐가 막힘 | `docker compose exec rabbitmq rabbitmqctl purge_queue news_queue` |
| DB 잠금 에러 | WAL 모드 + 재시도가 자동 처리. 지속되면 컨테이너 재기동 |
| ngrok URL 안 발급 | `.env`의 `NGROK_AUTHTOKEN` 확인. 무료 plan 한도 (분당 4번 새 터널) |
| 로그인 후 결과 안 보임 | 다른 사용자로 분석한 결과는 격리됨. 본인 계정으로 분석한 후 확인 |
| 모델 다운로드 실패 | Dockerfile의 `RUN python -c "...pretrained..."`가 빌드 시 미리 받음. 빌드 재시도 |
