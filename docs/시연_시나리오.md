**강조 포인트**: NLI 함의 막대 (녹색 entailment 90%+) 시각적으로 보여주기

---

### 구간 4 — 단일 분석 시연 (자극성 의심 기사) (1:10 ~ 1:40)

**화면**: 자극적 표현 많은 기사 URL 입력
- 결과: 종합 점수 60~79 "주의 필요" 또는 40~59 "의심 기사"
- NLI contradiction 막대 또는 자극성 단어 다수 검출

**멘트**:
> "이번에는 제목과 본문이 어긋나거나 자극적 표현이 많은 기사를 분석해 봅니다. NLI 모델이 모순(contradiction) 확률이 높다고 판정하거나, 자극성 사전에서 4개 카테고리 — 과장/혐오/선정/공포 — 의 단어들이 검출되어 점수가 큰 폭으로 감점됩니다. 단순한 가짜/진짜 이진 판정이 아니라, 점수와 근거가 함께 제공되는 설명 가능한 AI 구조입니다."

---

### 구간 5 — 대량 분산 분석 (1:40 ~ 2:50)

**화면**: 대시보드 → 대량 분석 → 20개 URL 일괄 입력
- 처리되는 동안 사이드바의 "Worker별 처리 현황" 막대그래프가 실시간 차오르는 모습
- 평균 분배 균등성 확인 (예: 7/7/6건)

**멘트**:
> "20건의 기사 URL을 일괄 분석합니다. RabbitMQ 큐가 작업을 3개 Worker에 자동 분배하며, 사이드바의 Worker별 처리 현황 막대그래프에서 분배가 거의 균등하게 이루어지는 것을 확인할 수 있습니다. Worker 한 대로는 약 12초가 걸리지만, 3대가 병렬로 처리하면 약 10초 내에 완료됩니다. 대시보드는 처리 진행률, 등급별 분포, 캐시 적중률을 실시간으로 시각화합니다."

**강조 포인트**: 좌측 사이드바 "⚡ 캐시 적중률" 위젯 (NLI 30%+ / 출처 60%+) 강조

---

### 구간 6 — 캐싱 효과 + Worker 스케일링 비교 (2:50 ~ 3:30)

**화면**: 대시보드 사이드바 → "🏎️ 성능 측정" 페이지 → 벤치마크 차트
- Worker 1/2/3개의 처리 시간 비교 막대그래프

**멘트**:
> "마지막으로, Worker 수에 따른 성능 비교입니다. 20건 처리 시 Worker 1개로는 12.2초, 2개로는 10.2초, 3개로는 10.1초가 소요됩니다. 더 흥미로운 것은 캐싱 효과로, 같은 도메인이나 같은 본문이 반복되면 LRU 캐시가 적중하여 처리 시간이 1.5초에서 0.22초로 약 7배 단축됩니다. 이것이 본 논문이 강조한 '캐싱 최적화'의 정량적 효과입니다."

## Q&A 대비 핵심 멘트 (라이브)

### Q1. "왜 NLI에 60%, TF-IDF/키워드에 각 20%의 가중치를 두었나요?"
A. NLI는 의미적 함의를 잘 잡지만 짧은 본문에서 불안정할 수 있어, 어휘 기반 보조 신호인 TF-IDF 코사인 유사도와 키워드 매칭을 결합했습니다. 60%/20%/20%는 NLI를 메인 신호로 두면서 보조 신호의 안정성도 확보하기 위한 초기 설계값이며, 실제 데이터로 추후 최적화할 계획입니다.

### Q2. "캐싱 최적화는 왜 했고 어떤 효과가 있나요?"
A. Worker별 LRU 인메모리 캐시를 NLI 추론, 감성 분석, 출처 분류 3종에 도입했습니다. 같은 도메인 또는 같은 본문 리드가 반복 입력되면 모델 추론을 생략하고 즉시 결과를 반환합니다. 캐시 적중 시 처리 시간이 1.5초에서 0.22초로 약 7배 단축됩니다.

### Q3. "단일 호스트에서의 분산 처리도 진짜 분산인가요?"
A. 네, 본 시스템은 분산 처리의 3가지 핵심 요건을 모두 충족합니다. (1) 부하 분산: RabbitMQ 라운드로빈 분배, (2) 장애 허용: `auto_ack=False` + 자동 재분배 + 최대 3회 재시도, (3) 수평 확장: docker-compose로 Worker 추가가 즉시 가능. 호스트네임으로도 컨테이너 ID가 모두 달라 독립된 노드임을 증명할 수 있습니다.

### Q4. "사용자화 기능이 있나요?"
A. 네, 학계 기본 가중치(45/35/20) 외에 사용자가 본인 기준으로 슬라이더로 조정할 수 있는 모드와, 분야별(정치/경제/연예) 프리셋 기능을 제공합니다. AI 판정을 사용자가 이해하고 통제할 수 있다는 XAI 철학에 부합합니다.

> ⚠ Q4는 E2/E4 구현 완료 후에만 답변 가능. 미구현 상태면 "현재는 학계 기본값 단일 모드이며, 사용자화는 향후 연구로 확장 예정"으로 답변.

## 시연 트러블슈팅

| 문제 | 즉시 조치 |
|---|---|
| Worker 컨테이너 안 떠있음 | `docker compose up -d worker-1 worker-2 worker-3` |
| 분석 시 404 (모바일 URL 변환 실패) | 사용자가 입력한 URL이 `comment/` 경로면 새 URL로 교체 |
| 큐가 막힘 | `docker compose exec rabbitmq rabbitmqctl purge_queue news_queue` |
| DB 잠금 에러 | Worker 1개만 일시 정지 → 자동 재시도 후 복구됨 |
| 모델 로딩 안 됨 | `docker compose logs worker-1 | grep 로딩` 확인 후 재기동 |
