# SSAK3 진위 판별(Fact-Checking) 방향 재설계 검토

> 사용자 요청: 현재의 "형식적 신뢰도 점수화"를 넘어 "**진위 판별(True/False)**"에 초점을 맞춰 처음부터 재검토.
> 작성일: 2026-05-12
> 결론 미리: **하이브리드 접근(현재 형식적 신뢰도 + 진위 판별 보강)을 권장**.

---

## 1. 현재 시스템의 한계 (왜 재설계가 필요한가)

### 1.1 "신뢰도 점수화" ≠ "진위 판별"

SSAK3 현 구조는 다음 3지표로 신뢰도를 점수화합니다:

| 지표 | 무엇을 측정하나 | 진위 판별 한계 |
|---|---|---|
| 본문 일치도 (45%) | 제목-본문 의미 함의(NLI) | 제목과 본문이 일치해도 **둘 다 거짓**일 수 있음 |
| 자극성 (35%) | 단어 사전 + 감성 모델 | 자극적이어도 **사실일 수 있음** (특종 보도) |
| 출처 (20%) | 매체 등록 여부 | 주요 언론사도 **오보 가능** |

→ 즉 본 시스템은 "글의 형식·표현·출처가 신뢰할 만한가"를 판단하지, "글의 내용이 사실인가"를 판단하지 않습니다.

### 1.2 한계 사례

**예시 A — 형식 신뢰 + 내용 거짓 (False Negative)**
- 제목: "한국은행, 기준금리 5% 인상 결정"
- 본문: 형식 정상 + 출처: 연합뉴스 위장
- 현 시스템 판정: 신뢰 가능 (85점) ❌

**예시 B — 형식 의심 + 내용 진실 (False Positive)**
- 제목: "충격! 정부 또 부실 정책 폭로"
- 본문: 자극어 다수 + 출처: 작은 매체
- 사실: 진실 보도
- 현 시스템 판정: 의심 (48점) — 사실은 진실인데 의심으로 분류 ❌

→ 진위 판별을 위해서는 **외부 지식 활용 (Knowledge-grounded)** 이 필수.

## 2. 진위 판별 시스템 설계 옵션 3가지

| 옵션 | 핵심 기술 | 학술 가치 | 구현 난이도 | 학회 발표용 적합도 |
|---|---|---|---|---|
| **A. 외부 팩트체크 DB 연동** | SNU 팩트체크 / Google Fact Check API | ⭐⭐⭐⭐ | 중 | ★★★★★ |
| **B. 다중 소스 교차 검증** | 같은 사건의 여러 매체 비교 | ⭐⭐⭐ | 중상 | ★★★ |
| **C. Claim Extraction + 검색** | NER + 사실 주장 추출 + 검색 | ⭐⭐⭐⭐⭐ | 상 | ★★★★ |

### 옵션 A — 외부 팩트체크 DB 연동 (가장 현실적)

```
사용자 입력 (URL)
  ↓
크롤링 (제목 + 본문)
  ↓
[새 단계] 본문 핵심 주장 키워드 추출
  ↓
SNU 팩트체크 / Google Fact Check API 검색
  ↓
일치하는 팩트체크 결과 있으면:
  · "검증된 거짓" → 즉시 의심/낮음 등급
  · "검증된 진실" → 신뢰 가능 등급
  · 부분 일치 → 부분 가중치 반영
없으면:
  · 기존 3지표(NLI + 자극성 + 출처) 분석으로 폴백
  ↓
최종 점수 + 등급 + **근거 (팩트체크 출처 표시)**
```

**장점**:
- 외부 검증된 사실 데이터 활용 → 학술적 무게 큼
- "객관적 진위 검증" 명분 확보
- SNU 팩트체크는 한국어 데이터셋

**단점**:
- API 호출 제한 (Google Fact Check: 무료 한도 있음)
- 모든 기사가 팩트체크 대상은 아님 (커버리지 한계)

**구현 예상 시간**: 6~8시간
- API 키 발급 + 호출 (1시간)
- 본문 키워드 추출 + 매칭 (2시간)
- 결과 통합 + 점수 산식 변경 (2시간)
- 대시보드 UI (팩트체크 결과 표시, 2시간)
- 테스트 + 회귀 평가 (1~2시간)

---

### 옵션 B — 다중 소스 교차 검증

```
사용자 입력 (URL)
  ↓
크롤링 (제목 + 본문 + 핵심 키워드)
  ↓
[새 단계] 같은 키워드로 다른 매체 검색 (네이버 뉴스 검색 API)
  ↓
최근 1주일 내 유사 기사 N건 수집
  ↓
원문과 N건의 사실 일치도 측정 (NLI / 임베딩 유사도)
  ↓
일치도가 높으면 → 다른 매체도 같은 사실 보도 → 신뢰
일치도가 낮으면 → 단독 보도 / 사실 어긋남 → 의심
```

**장점**:
- 외부 API 의존도 낮음
- 새로운 사건에도 적용 가능
- "여러 매체가 같이 보도하면 사실에 가깝다" 직관 부합

**단점**:
- 같은 출처(통신사)가 여러 매체에 뿌린 기사면 모두 일치 → 의미 약화
- 단독 보도가 거짓으로 분류될 위험
- 음모론 등 모든 매체가 거짓을 같이 보도하는 경우 못 잡음

**구현 예상 시간**: 8~10시간 (검색 + 유사도 계산 + 평가)

---

### 옵션 C — Claim Extraction + 검색 (가장 정통적 학술 접근)

```
사용자 입력 (URL)
  ↓
크롤링 (제목 + 본문)
  ↓
NER (개체명 인식): 사람·기관·날짜·숫자 추출
  ↓
Claim 추출: 본문에서 사실 주장 문장 N개 추출
  예) "한국은행이 5월 25일 기준금리를 3.25%로 동결했다"
  ↓
각 Claim을 검색 (Google 검색 API or 외부 지식)
  ↓
검색 결과 상위 N개와 비교:
  · 검색 결과 다수가 일치 → 사실
  · 일치 없음 → 거짓 가능성
  ↓
Claim별 진위 판정 → 종합 진위 점수
```

**장점**:
- 학술적 가치 매우 높음 (NLP 정수, 논문 가치 ↑)
- "왜 거짓으로 판정했는가" Claim별로 명확
- 한국어 NLP 응용 사례 강조 가능

**단점**:
- 한국어 NER + Claim 추출 모델 정확도 한계
- 구현 난이도 높음 (NER, Claim 추출, 검색, 통합 4단계)
- 검색 API 비용 / 제한

**구현 예상 시간**: 15~20시간 (학회 발표까지 시간 압박)

## 3. 권장안 — 하이브리드 (현재 시스템 + 진위 판별 보강 레이어)

### 3.1 설계 철학 변경

**기존**: "신뢰도 = 형식 + 자극성 + 출처" (3지표 100%)
**개선**: "**진위 판별 + 신뢰도**" (2단계 분류기)

```
1단계: 진위 판별 (외부 팩트체크 DB 조회)
  → 매칭되면 → 결정적 등급
  → 매칭 안 되면 → 2단계로

2단계: 형식 신뢰도 (기존 NLI + 자극성 + 출처)
  → 형식 분석 결과로 보조 등급

최종 출력: 진위 판별 결과 + 형식 신뢰도 결과 + 종합 판정
```

### 3.2 새 시스템 데이터 흐름

```
사용자 (URL)
   ↓
API → Worker
   ↓
크롤링 (제목 + 본문 + 출처)
   ↓
┌─────────────────────────────┐
│  Phase 1: 진위 판별         │
│  - 외부 팩트체크 DB 조회     │
│    (SNU 팩트체크 검색 API)   │
│  - Google Fact Check API     │
│  - 매칭되면 결과 직접 활용    │
└─────────────────────────────┘
   ↓
┌─────────────────────────────┐
│  Phase 2: 형식 신뢰도        │
│  - NLI 본문 일치도 (현재 유지)│
│  - 자극성 (현재 유지)         │
│  - 출처 (현재 유지)           │
└─────────────────────────────┘
   ↓
┌─────────────────────────────┐
│  Phase 3: 종합 판정          │
│  - 팩트체크 매칭: 100% 반영   │
│  - 매칭 없음: 형식 신뢰도만   │
│  - 두 가지 모두 표시          │
└─────────────────────────────┘
   ↓
대시보드 결과:
  · 진위 판별 결과 (사실/거짓/미확인 + 출처)
  · 형식 신뢰도 (현재 시스템)
  · 종합 판정 (사용자 친화 메시지)
```

### 3.3 새 점수 산식 (제안)

```
if 외부 팩트체크 매칭:
    진위_점수 = 팩트체크_결과 (사실=100, 거짓=0)
    형식_점수 = (현재 종합 점수)
    종합_점수 = 진위_점수 × 0.7 + 형식_점수 × 0.3
else:
    진위_점수 = N/A (미확인)
    형식_점수 = (현재 종합 점수)
    종합_점수 = 형식_점수 (단순 형식 신뢰도)
```

**효과**:
- 팩트체크 가능한 기사: 외부 검증된 진위 + 형식 검증으로 강한 판정
- 팩트체크 불가능한 기사: 기존 형식 신뢰도로 폴백 (시스템이 부서지지 않음)

### 3.4 새 등급 체계 (제안)

| 종합 점수 | 등급 | 의미 |
|---|---|---|
| 90+ | **검증된 사실** | 외부 팩트체크 매칭 + 형식 신뢰 |
| 80~89 | 신뢰 가능 | 형식 신뢰 (팩트체크 미매칭) |
| 60~79 | 주의 필요 | 형식 의심 신호 일부 |
| 30~59 | 의심 기사 | 형식 의심 다수 |
| 0~29 | **검증된 거짓** | 외부 팩트체크 거짓 매칭 |

→ 양극단 등급(검증된 사실/거짓)은 **외부 데이터 기반**이라 학술적 무게가 크게 증가.

## 4. 학회 발표 영향력 분석

### 현재 (형식적 신뢰도) — 발표 멘트
> "본문 일치도, 자극성, 출처 신뢰도 3지표로 뉴스의 **형식적 신뢰도**를 점수화합니다."

### 옵션 A 적용 후 — 발표 멘트
> "본 시스템은 **2단계 접근법**을 채택했습니다. 1단계로 SNU 팩트체크와 Google Fact Check API를 통한 **외부 검증된 진위 판별**을 시도하고, 매칭되지 않는 신규 기사는 2단계 형식 신뢰도 분석(NLI + 자극성 + 출처)으로 보조 판정합니다. 이를 통해 검증 가능한 사실은 결정적으로 분류하고, 아직 팩트체크되지 않은 기사도 형식 분석으로 신뢰도를 추정합니다."

→ **학술적 무게 큰 폭 상승**. "단순 형식 분석" → "진위 판별 + 형식 신뢰도 하이브리드".

## 5. 구현 로드맵 (옵션 A 기준, 권장)

### Phase T1 — 외부 팩트체크 API 통합 (3~4시간)
- T1-1. SNU 팩트체크 데이터셋 다운로드 또는 검색 API 활용
  (https://factcheck.snu.ac.kr/)
- T1-2. Google Fact Check Tools API 키 발급 + 호출
  (https://toolbox.google.com/factcheck/apis)
- T1-3. Worker에 fact_check 함수 추가:
  ```python
  def fact_check(title, body):
      # 본문에서 핵심 키워드 N개 추출
      # SNU + Google API 호출
      # 매칭 시 (verdict, source, confidence) 반환
      ...
  ```

### Phase T2 — 산식 + DB + 대시보드 통합 (2~3시간)
- T2-1. `analysis_results`에 `fact_check_result`, `fact_check_source`, `verity_score` 컬럼 추가
- T2-2. 종합 점수 산식 변경
- T2-3. 등급 체계 5단계로 확장 ("검증된 사실" / "검증된 거짓" 추가)
- T2-4. 대시보드 결과 카드에 팩트체크 섹션 추가

### Phase T3 — 평가 + 회귀 (1~2시간)
- T3-1. K1 평가 데이터셋에 "진위 판별" 케이스 추가
- T3-2. eval_runner에 fact_check 결과 측정 로직
- T3-3. 회귀 평가 (Loose Accuracy 90% 유지 확인)

### Phase T4 — 논문 보강 (1~2시간)
- T4-1. 본론 2.2에 "2단계 접근법" 명시
- T4-2. 결론에 "외부 검증된 진위 + 형식 신뢰도" 강조
- T4-3. 평가 결과 표에 진위 판별 정확도 추가

**총 예상 시간**: **7~11시간** (학회 발표까지 시간 있다면 충분)

## 6. 즉시 검토 가능한 실용 옵션 (시간 부족 시 축소판)

### 미니 T1 — SNU 팩트체크 정적 DB만 활용 (2시간)
- SNU 팩트체크 사이트에서 검증된 기사 N건 (제목 + 판정) CSV 다운로드
- worker에 사전 dict로 임베드
- 사용자 입력 제목과 SNU DB 제목의 유사도(코사인 > 임계) 매칭 시 결과 반영

이 정도만 해도 "외부 검증 데이터 활용" 학술 명분 확보 가능. API 호출 부담 없음.

### 미니 T2 — 키워드 화이트리스트 기반 알려진 거짓 차단 (1시간)
- 명백한 가짜뉴스 패턴 라이브러리:
  · "정부 발표 5G 인체 유해"
  · "백신 사망자 N만 명"
  · 등 잘 알려진 가짜뉴스 시그니처
- 매칭 시 즉시 의심 등급

→ 학술적으로는 약하지만 실용성 ★

## 7. 사용자 결정 옵션

다음 중 골라주세요:

**(α) 풀 T1~T4 진행** — 7~11시간, 학술 가치 + 발표 임팩트 최대화
**(β) 미니 T1 (SNU 정적 DB)** — 2시간, 빠른 구현 + 일부 학술 명분
**(γ) Phase T2~T3만 구현 (산식 + 평가)** — 4시간, T1은 mock으로 두고 구조부터 확립
**(δ) 형식 신뢰도 유지** — 0시간, 현재 시스템 그대로 + 논문 표현만 조정 ("형식적 신뢰도 추정 시스템"으로 명확화)

학회 발표가 다른 팀원이라는 점 + 현재 시스템이 이미 정량 평가(K1)에서 좋은 결과를 낸 점을 고려하면, **β (미니 T1)가 가장 ROI 좋음**:
- 2시간 추가 작업으로 "외부 검증된 사실 데이터 활용" 명분 확보
- 발표 멘트 강화 가능
- 핵심 시스템(NLI + 캐싱 + 분산 처리)은 그대로 유지

또는 **δ (현 시스템 명확화)** — 시스템을 더 손대지 않고 "본 연구는 진위 판별이 아닌 **형식적 신뢰도 추정**에 초점을 둔다"고 논문에 명시. 이러면 K1 평가 결과의 가치도 그대로 보존.

---

## 8. 권장 결정 (개인 의견)

**β (미니 T1: SNU 정적 DB) + 논문 표현 정합화**를 추천합니다.

이유:
1. 2시간 추가 투자로 "외부 검증 데이터 활용" 학술 명분 확보
2. 기존 시스템 / 정확도 / K1 결과 모두 보존
3. 발표 멘트: *"형식적 신뢰도와 SNU 팩트체크 데이터를 결합한 하이브리드 접근"*
4. 실패 위험 매우 낮음 (외부 API 없이 정적 데이터만 사용)
5. 학회 후 시간 있을 때 옵션 A (풀 API)로 확장 가능

**사용자가 시간을 더 투자할 의사가 있다면** α (풀 T1~T4)로 가도 좋습니다. 다만 학회 발표 일정과 다른 보강 작업(K2 시연 영상, 논문 v3 적용, 팀원 피드백 반영 등)을 함께 고려해서 결정해주세요.

진행 결정 알려주시면 바로 착수하겠습니다.
